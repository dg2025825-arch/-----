## 4. 분석 과정 (10단계)

> 각 단계는 "무엇을 · 어떻게 · 왜" 한 줄씩. 아래는 초안이며, **실제로 한 일에 맞게 수정**하세요.

| 단계 | 무엇을 | 어떻게 | 왜 |
|---|---|---|---|
| 1. 데이터 수집 | Fitbit 활동·수면 파일 확보 | kagglehub로 다운로드, 폴더 구조와 컬럼 확인 | 질문에 필요한 열이 있는지 먼저 확인하려고 |
| 2. 변수 선택 | 입력(활동)과 목표(수면) 정하기 | 입력: VeryActive/FairlyActive/Lightly/Sedentary 분, TotalSteps 등. 목표: 수면 효율 또는 수면 부족 여부 | 질문과 직접 관련된 변수만 사용 |
| 3. 전처리 | 중복·미착용일·낮잠 기록 제거 | 중복 행 삭제, TotalSteps=0이고 좌식 1440분인 날 제외, 수면 [ ]분 미만 제외 | 기기 미착용이나 부분 기록이 결과를 왜곡하지 않게 |
| 4. 분할 | 학습/검증 나누기 | 사용자 단위로 분할(GroupKFold) | 같은 사람의 여러 날이 양쪽에 섞이면 성능이 부풀려지므로 |
| 5. 기준선 | 아무것도 안 하는 모델 만들기 | 다수 클래스 예측(분류), 평균 예측(회귀) | 모델이 의미 있는지 비교할 바닥선이 필요해서 |
| 6. 후보 모델 비교 | 여러 모델 학습 | 로지스틱, 결정트리, 랜덤포레스트, 선형회귀 등 | 한 모델만 쓰면 "최선"이라 말할 수 없어서 |
| 7. 선택 | 최상의 모델 고르기 | 교차검증 점수와 안정성(분할별 편차) 비교 | 점수 하나가 아니라 흔들림까지 봐야 해서 |
| 8. 평가 | 선택한 모델 점검 | 균형 정확도, 혼동행렬, [회귀: MAE, R²] | 한쪽 클래스가 많을 때 정확도의 착시를 피하려고 |
| 9. 해석 | 왜 그 모델이 나았는지 분석 | 변수 중요도, 오분류 사례 확인 | 점수보다 이유가 핵심 |
| 10. 한계 점검 | 결과의 한계 정리 | 표본 수, 기간, 기기 오차, 수면 부족 기준의 임의성 | 과한 일반화를 막으려고 |
